# Evidence workspace release · September 10, 2026

This release makes the project easier to review and blocks progression that its evidence has not earned. It is a separate checkout based on `9808b0e`. The original running paper engine was not stopped, replaced or redeployed.

## Delivered

- Six views: overview, source-linked historical evidence, a filterable test plan, connected paper-engine observation, six live-pilot gates, and proposed service pricing with a delivery-cost calculator.
- The shared Google Doc contains the assessment, evidence archive, $1,500 pilot hypothesis, unit economics, customer/research/engineering tests, responsibilities and all six pilot requirements. Taj has commenter access; the original evidence files are shared read-only.
- Historical failed and inconclusive results remain immutable snapshots. Current engine readings are separately timestamped; backend outages are shown as unavailable rather than fabricated stopped/healthy states.
- Live broker selection and direct order submission are blocked. Startup always disarms. HTTP mutations require an explicit server token; an unset token disables them. Legacy forward begin/replay/reset routes refuse to alter the ledger even with `force=true`.
- Paper exits reject pre-entry and forming bars, process retained eligible events chronologically, ignore duplicates and use adverse opening prices when gaps cross stops. Unexplained history gaps remain flagged and prevent finalizing an exit as reconciled P&L. Corrupt paper-state JSON fails instead of resetting the balance.
- Paper and historical V2 replay use one trailing helper: activate at +1R, retain activation, ratchet without widening and respect tick increments. A rejected broker stop update cannot change the recorded acknowledged stop.
- The optional ML labeler handles short outcomes symmetrically, omits incomplete label horizons and purges six rows before the chronological test boundary. No new ML strategy was trained or evaluated.
- Default host binding is loopback. Docker host port mappings are loopback-only; the frontend uses a server-side upstream setting. Docker build contexts and lockfile installation were corrected, but a Docker image was not built in this review.
- Next.js was upgraded to maintenance release 15.5.25 and dependency audit findings were repaired, including a PostCSS 8.5.28 override. See the [official August security release](https://nextjs.org/blog/august-2026-security-release) and [Next.js 15 migration guide](https://nextjs.org/docs/app/guides/upgrading/version-15). No async request-API migration was needed in the existing routes.

## Verification

The isolated backend runner passes 98 tests (83 existing and 15 new), without production state, market downloads or external order routing. New coverage includes pre-entry/duplicate/missed-event handling, gap execution, unacknowledged stop changes, incomplete labels, corrupted state, adapter blocks, API authentication and blocked campaign rewrites. Frontend TypeScript checking and the production build pass. The dependency audit reports zero known vulnerabilities at review time.

The original synthetic application probes were rerun with only the checkout path changed. Compare `frontend/public/evidence/app-probes.json` with `docs/repair-probes-2026-09-10.json`: the pre-entry exit changes from true to false, the premature stop changes from 99.5 to 90, and short labels change from zero to 24. These are synthetic regression outcomes, not performance results.

Browser verification covers desktop and mobile rendering, navigation, source expansion, category filtering, paper-backend reads, calculator sensitivity and explicit unavailable states. A $1,500 job at 8 hours, $75/hour and $100 tooling yields $800 contribution; at 20 hours it yields −$100. Neither is a revenue forecast. A fresh preview boot with `TRADING_ENABLED=true` still returned entries disabled and scheduler stopped.

## What remains open

No live gate is verified. This is not a completed automated validation pipeline or a broker-certified execution system. In particular:

1. Nullius still needs sealed observation provenance and access history, overlap rejection, corrected verdict logic, dependence-aware inference, complete search-family accounting and ledger custody. The pre-existing economics working-tree patch remains separately preserved.
2. Real broker adapters still need contract mapping, durable pending/partial order state, protective-order acknowledgment, disconnect/rejection behavior and restart reconciliation. They are blocked here, not represented as complete.
3. Paper execution still has OHLC ambiguity, a Yahoo proxy feed, limited retained history, no complete session/roll calendar and unproven fill latency/queue assumptions. The partial entry bar is excluded rather than used retrospectively. Shared trailing logic is not proof of full replay/paper parity, especially across missed cycles.
4. Full historical results must be reproduced under the repaired rules before any new performance claim. No previously unseen dataset was opened and no live pilot was authorized.
5. Buyer demand, payment, delivery economics and renewals have not been established. The next commercial test remains two independently paid evaluations within a defined scope.

The next engineering milestone is one end-to-end, frozen, reproducible evaluation with trustworthy provenance and report consistency. The master plan describes the acceptance criteria. Keep this release and the original assessment distinguishable; software repairs do not erase failed research.
